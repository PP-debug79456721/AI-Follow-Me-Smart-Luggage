### 2.1 ซิงก์ repo กับเครื่องจริง (ข้อ 1)
- ตรวจว่าโน้ต `CLAUDE.md` ตรงกับ repo (ตรงเกือบทั้งหมด) แล้วเพิ่มสิ่งที่ขาด: `firmware/esp32-follow/backup-phase1/` และบรรทัดป้าย DEVICE BUSY ที่เคยอยู่แค่ในแล็ปท็อป
- เหตุผลของบรรทัดป้าย: session ตั้ง `desired=false` ทันทีที่เจอ DEVICE_BUSY เงื่อนไขเดิมจึงไม่เคยแสดงป้าย

### 2.2 ตัวตรวจจับคนและตัวติดตาม (ข้อ 3-4)
- วิเคราะห์วิดีโอหน้าจอของคุณ: เลขกล่องติดตามเพิ่มจาก #4 ถึง #8 ในคลิปเดียว ความมั่นใจของกล่องอยู่ที่ 50-66% (เฉียดเกณฑ์ 0.5) และมีภาพกล้องดำสองช่วง
- อ่านโค้ด `person-tracker.js` พบว่าเลขเพิ่มเฉพาะตอนเลือกคนใหม่ (แตะซ้ำหรือเลือกอัตโนมัติ) หลังเป้าหายเกิน 2.5 วินาที และตัวติดตาม **ไม่มีการทำนายตำแหน่ง** กล่องที่เลือกจะค้างอยู่ที่ตำแหน่งสุดท้าย
- ที่แก้: `PERSON_SCORE_THRESHOLD = 0.35` และตัวนับ `MISS n/60s` บนการ์ด PERSON DETECTION
- ผลวัดล่าสุดของคุณ: `1 PERSON · 217 ms · GPU · MISS 22/60s` (≈ 8% ของรอบตรวจพลาด) ยังไม่มีตัวเลข MISS "ก่อนแก้" มาเทียบ จึงยังสรุปไม่ได้ว่าดีขึ้น

### 2.3 ฮาร์ดแวร์: โซนาร์และความปลอดภัย (ข้อ 2, 5)
- วาดแผนผังต่อสายโซนาร์ HC-SR04 สองตัว (ตัวแบ่งแรงดัน ECHO 1k/2k, ตำแหน่งติดตั้งจากวิดีโอ): https://claude.ai/artifact/2wpKe6ftUnYC6aTYrH5jZe (เปิดได้เฉพาะเจ้าของ)
- ปิดโซนาร์ใน firmware จนกว่าจะต่อสายจริง และลด duty เป็น 0.60 ตามคำแนะนำใน `CLAUDE.md` เรื่องฟิวส์ที่ยังไม่ได้ติด

### 2.4 ลดภาระและความร้อนบนมือถือ (ข้อ 6, 8)
- **lite อัตโนมัติบนมือถือ** (`js/lite-mode.js`): `?lite=1` บังคับเปิด, `?lite=0` บังคับปิด ถ้าไม่ระบุจะตรวจว่าเป็นมือถือ กล้องเป็น 320x240 ที่ 12-15 fps ไม่ตรวจใบหน้า
- **A:** วาดภาพซ้อนสูงสุด ~15 ครั้ง/วินาทีในโหมด lite
- **B:** `looksBlocked()` (อ่านพิกเซลกลับจาก GPU) ทำแค่วินาทีละครั้ง
- **C:** ตรวจจับทุก 500 ms ตอนยังไม่ FOLLOW แล้วกลับเป็น 200 ms เมื่อเปิด FOLLOW (`setFollowActive` จาก `app.js`)
- **D:** ขึ้น `เครื่องช้า/ร้อน` เมื่อ INF เฉลี่ย > 250 ms
- ข้อสังเกตที่ผมเคยพูดเกินไป: การลดความละเอียดกล้องแทบไม่ช่วย INF เพราะโมเดลย่อภาพเป็น 320x320 เสมอ ช่วยได้แค่ค่าถอดรหัส/คัดลอกภาพ

### 2.5 Bluetooth LE ฝั่ง firmware (ข้อ 7, 10)
- ไฟล์ใหม่: `transport_router.h` (รวมสองช่องทางเข้า safety kernel ตัวเดียว), `ble_server.h` (Nordic UART service), `ble_framing.h` (ตัดบรรทัด/คิว/แบ่งก้อน ทดสอบบน host ได้)
- กฎความปลอดภัยที่ใช้: คำตอบกลับไปยังช่องที่ส่งข้อความมา, **ช่องไหนก็ตามหลุด มอเตอร์หยุดทันที**, โปรโตคอลและ kernel ไม่ถูกแก้
- `config.h`: `kEnableWifi`, `kEnableBle`, `kBleName = "FollowMe-Luggage"`, `kBleMaxChunk = 180`
- serial เพิ่ม `wifi=<รหัสสถานะ>` และ `ble=<ต่ออยู่>/<จำนวนครั้ง> bledrop=<เข้า>/<ออก>`
- ต้องตั้ง Tools → Partition Scheme → **Huge APP (3MB No OTA/1MB SPIFFS)** ไม่เช่นนั้นขึ้น `Sketch too big` (คุณเจอและแก้แล้ว)
- แก้ CCCD (ข้อ 10): ช่อง TX ไม่มี descriptor 2902 แอปมือถือจึงขึ้น `no CCCD` เพิ่ม `BLE2902` ทุกเวอร์ชัน core (ผมเคยสมมติผิดว่า core 3.x เพิ่มให้เอง)

### 2.6 Bluetooth LE ฝั่งหน้าเว็บ (ข้อ 9)
- `js/ble-socket.js`: ทำให้ Web Bluetooth ทำตัวเหมือน WebSocket จึงไม่ต้องแก้ session/link/โปรโตคอล ใส่ URL `ble://` (หรือ `ble://?chunk=100`)
- `esp32-session.js`: socket กำหนดเวลารอเปิดเองได้ (BLE 30 วินาที เพราะหน้าต่างเลือกอุปกรณ์)
- `app.js`, `index.html`: URL ขึ้นต้น `ble:` ใช้ตัวนี้, ปรับป้ายและ placeholder ช่อง URL
- ข้อจำกัดที่รู้: เลือกอุปกรณ์ต้องกด CONNECT เอง (ต้องมี user gesture) ใช้ได้เฉพาะ Android Chrome

## 3. ผลวัดจากการทดสอบจริงของคุณ

### 3.1 มือถือ Infinix Note 30 5G (ตัวตรวจจับคน)
| สถานการณ์ | ระยะห่างตรวจ | INF เฉลี่ย/สูงสุด |
|---|---|---|
| เริ่มต้น (เครื่องเย็น) | 200-284 ms | 182 / 223 ms |
| หลังเปิดไว้ ~10 นาที (เครื่องร้อน) | 230-300 ms | **270 / 402 ms** |
| หลังมาตรการ A-D (ยังไม่ FOLLOW) | 500 ms | 199 / 272 ms |

ผมยังไม่ได้ผลของช่วง **FOLLOW เปิด 10 นาที** ซึ่งเป็นช่วงที่ร้อนจริงและเป็นตัวตัดสินว่ามาตรการพอหรือไม่

### 3.2 RTT ของลิงก์
| ลิงก์/สถานการณ์ | RTT |
|---|---|
| Wi-Fi บนแล็ปท็อป (จาก `CLAUDE.md`) | 10-30 ms |
| Wi-Fi บนมือถือ (จาก `CLAUDE.md`) | 300+ ms |
| BLE `ble://` | 100-300 ms |
| BLE `ble://?chunk=100` | 100-300 ms (ไม่เปลี่ยน) |
| BLE ปิดกล้อง | 100-300 ms (ไม่เปลี่ยน) |
| BLE หลังปิด Wi-Fi ของบอร์ด (`kEnableWifi=false`) | **60-291 ms** (ค่าต่ำสุดดีขึ้น ค่าสูงสุดเท่าเดิม) |

สิ่งที่ตัดออกแล้ว: ตัวตรวจจับยึด thread (ปิดกล้องแล้วไม่เปลี่ยน) และขนาดก้อนข้อมูล (chunk 100 ไม่เปลี่ยน) ที่ยังสงสัย: Wi-Fi ของมือถือรบกวน BLE และช่วงเชื่อมต่อ (connection interval)

### 3.3 Serial ของบอร์ด
- บูตปกติ: `PHASE 2: MOTOR OUTPUT ENABLED`, `obstacle check: OFF`, `state=BOOT_LATCHED motor=STOP relay=OFF` (สภาพปกติจนกว่าจะ ARM)
- Wi-Fi: `wifi=6` (WL_DISCONNECTED) เกือบตลอด, `rssi` -55 ถึง -75 ดูเหมือนเกาะสัญญาณแล้วหลุดวน ไม่ได้ IP เลย
- BLE: `ble=1/1` หลังต่อสำเร็จ `bledrop=0/0`

## 6. ปัญหาที่ยังเปิดอยู่

| ลำดับ | เรื่อง | สถานะ / ขั้นต่อไป |
|---|---|---|
| 1 | **Wi-Fi ของ ESP32 ไม่ได้ IP** | ไม่ทราบสาเหตุ สงสัยรหัสผ่านหรือโหมดความปลอดภัย (WPA3/PMF) ข้อเสนอที่ยังรอ: เพิ่มตัวพิมพ์ disconnect reason ใน firmware ตอนนี้ใช้ BLE แทนได้ |
| 2 | **RTT ของ BLE ยังแกว่ง (60-291 ms)** | ทดสอบต่อ: ปิด Wi-Fi ของมือถือแล้ววัด ถ้ายังสูง ปรับช่วงเชื่อมต่อฝั่ง firmware |
| 3 | อาการหยุดๆ จากการเสียเป้า | รอผลทดสอบ MISS เพิ่ม ถ้ายังสูงทำข้อ B (ทำนายตำแหน่ง) และ C (กันสลับตัวตอนคนยืนชิด) |

## 8. วิธีนำไปใช้ (สรุป)

**หน้าเว็บ** (คัดลอกไปที่ `C:\follow-app\js\` ให้ครบ ลืมไฟล์ใหม่ไม่ได้):
`ai-owner.js`, `app.js`, `camera.js`, `esp32-session.js`, `lite-mode.js` (ใหม่), `ble-socket.js` (ใหม่), และ `index.html` (อยู่ที่ราก `C:\follow-app\`)
แล้วรีเฟรช Ctrl+F5 และบนมือถือตั้งแฟล็ก `chrome://flags` "Insecure origins treated as secure" ให้ตรงกับ IP แล็ปท็อปปัจจุบัน

**Firmware** (ปิด Arduino IDE ก่อนวางไฟล์ **เก็บ `wifi_secrets.h` เดิมไว้**):
แตกชุดไฟล์ `esp32-follow` ทับ ตั้ง Partition Scheme = Huge APP, Verify แล้ว Upload ตัวสลับ `kEnableWifi`/`kEnableBle` อยู่ใน `config.h`

**ทดสอบ BLE:** ใส่ URL `ble://` ในช่อง ESP32 LINK กด CONNECT เลือก `FollowMe-Luggage` ปิดแอปอื่นที่ต่อ BLE ค้างอยู่ก่อน
