## ส่วนที่ 1 · สรุปงานของวันนี้

### 1.1 เป้าหมายและผลโดยสรุป

เป้าหมาย: แก้อาการ **ล้อขยับแปบ ๆ แล้วหยุด**, **ARM/FOLLOW หลุดบ่อย**, **DEVICE BUSY**, **ออกตัวกระชาก**, **กล้อง fps ต่ำ**, **ตรวจคนช้า**

| ปัญหา | สาเหตุที่ไล่เจอ | สิ่งที่ทำ | ผลที่ผู้ใช้รายงาน |
|---|---|---|---|
| ล้อหยุด-เดินบ่อย | BLE: RTT 200–500 ms และข้อความถูกปฏิเสธ ~6 % · ต่อมาเป็นเธรดหลักของมือถือหนัก (rtt 330 ms) | เปลี่ยนไปใช้ Wi-Fi · ย้ายตรวจคนไป Web Worker · ลดงานตอน FOLLOW | `rtt` ไม่เกิน 200 ms · อาการดีขึ้น |
| DEVICE BUSY | เซสชันเก่าค้าง ~1.2 วินาทีหลัง Wi-Fi สะดุด · และอาจมีหน้าเก่าเชื่อมต่อเองอยู่ | ปิดหน้าเก่า · เพิ่มตัวนับ `BUSY xN` บนการ์ด | **ขึ้นน้อยลง ใช้งานได้ถี่ขึ้น** (สาเหตุแท้จริงยังยืนยันไม่ได้) |
| ออกตัวกระชาก | ramp 2.5/วินาที = 0.24 วินาทีถึงกำลังเต็ม | `kRampPerSecond` 2.5 → 1.0 → 0.6 | **ออกตัวดีขึ้น** |
| fps กล้อง < 10 | ขอ 12 fps ทำให้มือถือเลือกช่วง fps ต่ำตอนแสงน้อย | ขอ 30 fps + ข้อความเตือนบนภาพถ้ายังต่ำ | ยังไม่ได้รายงานผล |
| ตรวจคน 500 ms+ | 500 ms คือช่วงรอก่อน FOLLOW (ปกติ) · ตอน FOLLOW ต้องรอรอบเฟรม | ตรวจทุก 150 ms ต่อเนื่องกับผลก่อนหน้า | ยังไม่ได้รายงานผลตัวเลข |
| หาเจ้าของที่หลุดไม่เจอ | **บั๊กที่ผมทำเอง** ตอนทำ worker: ฟังก์ชันเจ้าของไม่เคยทำงานเลย | แก้เวลาที่ส่งให้ฟังก์ชัน + เทสต์กันซ้ำ + ใช้ Re-ID ร่วมกับสีเสื้อ | **ยังรอผลทดสอบ** |
| หยุดไกลเจ้าของ | ตัวทำนายตำแหน่งขยายขนาดกรอบด้วย ทำให้ถึง 95 % เร็ว | ทำนายเฉพาะตำแหน่ง ไม่ทำนายขนาด | ยังรอผลทดสอบ |
| เดินตามไม่ทันคน | กำลังมอเตอร์ (`kDriveDuty` 0.60) | **ยังไม่ได้แก้** รอฟิวส์ | ดูส่วน 1.5 |

## ส่วนที่ 2 · เตรียมระบบ (ทำครั้งเดียว หรือเมื่อเปลี่ยนไฟล์)

### 2.1 ความปลอดภัยก่อนเริ่ม (อ่านก่อนจ่ายไฟ)

- **ติดฟิวส์ 10 A ก่อน** ที่สายบวกของแบตเตอรี่ ใกล้ขั้วแบตเตอรี่ที่สุด และ **ก่อนสวิตช์หลัก/ก่อนทุกสาขา** ลำดับ: แบตเตอรี่ (+) → ฟิวส์ → สวิตช์หลัก → (LM2596 → ESP32) และ (สวิตช์ E-STOP → คอยล์รีเลย์; รีเลย์ → B+ ของไดรเวอร์ทั้งสอง) ใช้ฟิวส์แบบเสียบ (blade) 10–15 A กับสายที่รับกระแสได้ไม่ต่ำกว่าค่าฟิวส์ ติดตอนถอดแบตเตอรี่ออก และใส่ฟิวส์เป็นลำดับสุดท้าย
- ตรวจสายทุกเส้นขันแน่น โดยเฉพาะ GND ของไดรเวอร์ทั้งสองตัวที่ไปช่อง GND ของฐาน และ VCC ไปช่อง 3V3 ไม่ใช้หัวดูปองต์เสียบเข้าช่องสกรู
- แนะนำให้ใส่ไดโอดคร่อมคอยล์รีเลย์ (flyback) · ไฟ LM2596 ควรวัดให้ได้ ~5.0 V ก่อนต่อ ESP32
- **ยกล้อลอยทุกครั้ง**เมื่อทดสอบใหม่หรือเปลี่ยนค่า · มีคนถือสวิตช์ E-STOP ตลอดช่วงสาธิต · อย่าต่อแบตเตอรี่มอเตอร์ตอนบอร์ดบูตวนหรือกำลังแก้สาย
- กฎความปลอดภัยที่ตกลงกันไว้ (ห้ามแก้): ไม่มีโหมด "ไม่หยุด" · ESTOP, ลิงก์หลุด, เจ้าของหาย, กล้องหลุด = หยุดเสมอ · สวิตช์ E-STOP ฮาร์ดแวร์เป็นตัวตัดอิสระ

### 2.4 เฟิร์มแวร์

ใน Arduino IDE (บอร์ด ESP32 Dev Module · Partition Scheme ปกติ เพราะ BLE ปิด) แก้ `config.h` ตามนี้ แล้วอัปโหลด

```cpp
constexpr float kRampPerSecond = 0.6f;   // ออกตัวนุ่ม (1.0 = เร็วขึ้น, 0.4 = นุ่มขึ้น)
```

- `wifi_secrets.h` ต้องใส่ชื่อ/รหัสผ่านของ hotspot (**ห้าม commit และห้ามวางรหัสในแชต**)
- ความเร็วเดินตาม `kDriveDuty` (เดิม 0.60): **ปรับได้เมื่อมีฟิวส์แล้วเท่านั้น** ทีละ 0.05 ไม่เกิน **0.72** (เกินแล้วล้อขวาที่คูณ 1.10 ชนเพดาน 0.80 ทำให้เดินเอียง)
- ถ้าบูตวนหลังอัปโหลด: ถอดบอร์ดออกจากฐานเทอร์มินัลแล้วอัปโหลดใหม่ (เปิด Erase All Flash) ต่อด้วยตรวจสายตามส่วน 5

### 2.5 มือถือ (Android Chrome) ผ่าน adb

```powershell
cd C:\platform-tools
.\adb devices
.\adb connect 192.168.137.152:<พอร์ตจากหน้า Wireless debugging>   # พอร์ตเปลี่ยนทุกครั้งที่เปิดปิด
```

- ใช้สาย USB ก็ได้ (ไม่ต้องต่อ Wi-Fi สำหรับ adb) ท่อ `adb reverse` ทำให้ `localhost:8000` บนมือถือชี้ไปเซิร์ฟเวอร์บนคอม และเป็น secure context (ไม่ต้องตั้ง chrome://flags) · **ต้องเป็น `localhost` เท่านั้น** (`modelMode=development` ใช้ได้เฉพาะ localhost)

3. เปิดหน้าบนมือถือ (แท็บเดียวเท่านั้น และปิดหน้าเดียวกันบนโน้ตบุ๊ก/เครื่องอื่นให้หมด)
4. **START CAMERA** → รอแถว READY ครบ → ยืนห่าง 2–3 เมตรให้เห็นทั้งตัว
5. **เลือกเจ้าของ**: แตะกรอบตัวเองจนขึ้น TRACKING (กรอบสีส้ม)
6. ใส่ `ws://192.168.137.50:81/ws` → **CONNECT** → ขึ้น `CONNECTED (STOP)`
7. **ARM → FOLLOW** แล้วเดิน (ยกล้อลอยทดสอบก่อน)
8. เลิกใช้: กด **DISCONNECT** (เพื่อไม่ให้หน้าเชื่อมต่ออัตโนมัติ)

### 3.2 ลิงก์ที่ใช้

| ต้องการ | ลิงก์ |
|---|---|
| ใช้งานปกติ (ตัดใบหน้า เบา) | `http://localhost:8000/?modelMode=development&lite=1&mode=demo&worker=1` |
| มีใบหน้า/ลงทะเบียนใบหน้า (หนักกว่า) | `http://localhost:8000/?modelMode=development&lite=0&mode=demo&worker=1` |
| แท็กอย่างเดียว ไม่ใช้ Re-ID | ต่อท้าย `&reid=0` |
| เทียบกฎหาเจ้าของแบบเดิม (Re-ID อย่างเดียว) | ต่อท้าย `&fuse=0` |
| ปิดการทำนายตำแหน่ง | ต่อท้าย `&predict=0` |

พารามิเตอร์ทั้งหมดต่อท้าย URL ได้ (ไม่ทำให้ข้อมูลเจ้าของหาย เพราะ origin ยังเป็น `localhost:8000`)

| พารามิเตอร์ | ผล |
|---|---|
| `lite=1` / `lite=0` | โหมดเบา (ไม่ตรวจใบหน้า) / โหมดเต็ม |
| `worker=1` | ตรวจคนใน worker (การ์ดขึ้น `GPU · WORKER`) ถ้าเริ่มไม่ได้ขึ้น `· MAIN (worker unavailable)` |
| `mode=demo` | ผ่อนเกณฑ์อายุข้อมูล/หลักฐาน และเกณฑ์ `rtt` 450 ms |
| `modelMode=development` | อนุญาตโหลดโมเดล Re-ID/ใบหน้า (เฉพาะ localhost) |
| `reid=0` | ไม่ใช้ Re-ID |
| `fuse=0` · `reidfloor=0.55` | กฎหาเจ้าของแบบเดิม · เกณฑ์ Re-ID ต่ำสุดที่สีเสื้อช่วยยืนยัน (ค่าเริ่มต้น 0.50) |
| `predict=0` | ปิดการทำนายตำแหน่ง |
| `stop=0.9` | เปลี่ยนเกณฑ์หยุดเมื่อใกล้ (ค่าเริ่มต้น 0.95 สูงสุด 0.95) |
| `learn=0` | ไม่เรียนรู้อัตโนมัติขณะติดตาม |

### 3.3 ลงทะเบียนเจ้าของ (ทำครั้งแรก หรือเมื่อเปลี่ยนชุด)

1. ยืนคนเดียวในภาพ แตะกรอบตัวเอง (TRACKING)
2. กด **REMEMBER CLOTHES** (เริ่มอัลบั้มใหม่ ทั้งสีเสื้อและ Re-ID)
3. หันตัว/ขยับเป็นมุมอื่น (หลัง หน้า ข้าง) แล้วกด **ADD VIEW** ทีละมุม จนบรรทัด OWNER ขึ้น `จำเสื้อผ้า n/8 มุม · Re-ID n/12`
4. ข้อมูลอยู่ในมือถือ (ผูกกับ `localhost:8000`) ปิดแล้วเปิดใหม่ด้วย URL เดิมข้อมูลยังอยู่ จะหายถ้าล้างข้อมูลเว็บไซต์/ใช้โหมดไม่ระบุตัวตน/เปลี่ยนไปใช้ IP อื่น
5. เปลี่ยนเสื้อผ้า = ลงทะเบียนใหม่ (หรือเพิ่มมุม) · ปุ่ม FORGET OWNER ลบข้อมูล · มีได้ 3 โปรไฟล์ (ใช้ได้ทีละหนึ่ง)

### 3.4 ถ้าเจ้าของหลุดจากภาพ

- สถานะ: TRACKING → SEARCHING (~2.5 วินาที) → LOST **ล้อหยุดตั้งแต่หายไป**
- กลับมายืนนิ่ง ๆ ในภาพ 3–5 วินาที แล้วกด **FIND OWNER** (หรือแตะกรอบตัวเองใหม่)
- กฎหาเจ้าของ: Re-ID ≥ 65 % **หรือ** Re-ID 50–64 % ร่วมกับสีเสื้อ ≥ 80 % (สีนำคนอื่น 6 %, Re-ID นำ 5 %) ต้องผ่าน 3 จาก 5 รอบ ถ้ากำกวมจะไม่เลือกใคร (ปลอดภัยกว่าตามผิดคน) · ถ้าเจอจากกฎร่วม ป้ายจะเป็น "เสื้อผ้า/ยังไม่ยืนยัน" และไม่เรียนรู้ต่ออัตโนมัติ
- **แตะกรอบเองเป็นทางสำรองเสมอ**

### 3.5 อ่านค่าบนหน้าจอ

| จุด | ความหมาย |
|---|---|
| PERSON DETECTION | `1 PERSON(S) · 150–250 ms · GPU · WORKER · LIB CDN · INF avg/max · LAT` ช่วงห่าง ~500 ms ก่อน FOLLOW ในโหมดเบาคือช่วงรอ (ปกติ) · INF avg เกิน 250 ms ขึ้น `เครื่องช้า/ร้อน` |
| OWNER | `จำเสื้อผ้า … · Re-ID … · ค้นหา Re-ID 58% (0.58) · เสื้อ 84% (0.84)` หรือ `ค้นหา: ไม่เห็นคนในภาพ` / `กำลังคำนวณ…` |
| MOTOR COMMAND | STOP/FORWARD/LEFT/RIGHT และความสูงกรอบ % (หยุดเมื่อ ≥ 95 % เริ่มเดินใหม่เมื่อต่ำกว่า 87 %) · ศูนย์กลางกรอบเลย 60 % ทางขวา = RIGHT, ต่ำกว่า 40 % = LEFT, ช่วงกลางตรง |
| ESP32 (การ์ดรายละเอียด) | `rtt` (ควร < 300 ms), `page stall` (100 ms = พื้นฐาน), `stops:` สาเหตุที่ล้อหยุดบ่อยที่สุด (`STALE_DECISION`, `RTT_GATE`, `PROOF_EST_STALE`, `BUSY xN`) |
| ป้าย fps บนภาพ | ถ้าต่ำกว่า 10 fps ติดต่อกัน 5 วินาทีขึ้น `· ต่ำ: แสงน้อย/เครื่องหนัก` |
| Serial บอร์ด | `wifi=3` เชื่อมต่อแล้ว · `rssi` ควรดีกว่า −65 · `rej=0` · `maxgap` ~13 · `wd=0` |

### 3.6 เงื่อนไขที่ล้อหยุดเสมอ

เจ้าของหาย/ไม่แน่ใจตัวตน · ข้อมูลเก่าเกิน (อายุ > 450 ms; DEMO 1,200 ms) · `rtt` เกินเกณฑ์ · ลิงก์/Wi-Fi หลุด · กล้องหลุด · กด ESTOP · เจ้าของใกล้เกินไป (กรอบ ≥ 95 %) · เจ้าของไกลเกินไป (กรอบเล็กกว่า 10 % ของความสูงภาพ)

## ส่วนที่ 4 · วันนำเสนอ (กรรมการ + ผู้นำเสนอ 3 คน)

- **ผู้นำเสนอที่แต่งตัวเหมือนกัน** แยกด้วยสีเสื้อไม่ได้ ระบบเลือก "ไม่มีใคร" ถ้ากำกวม · ให้เจ้าของมีของสีสดที่ไม่มีใครมีติดที่ลำตัว (ผ้าคาดแขน/เสื้อกั๊ก) แล้วกด REMEMBER CLOTHES ตอนใส่ของนั้น
- เจ้าของเดินนำโดดเดี่ยว คนอื่นยืนด้านข้างห่างจากแนวเดิน ไม่เดินตัดหน้าเจ้าของ
- แตะกรอบเจ้าของเองก่อนกด FOLLOW ทุกครั้ง · มีคนถือสวิตช์ E-STOP · ยังไม่มีเซ็นเซอร์กันชน
- ใช้ `lite=1` ตอนสาธิต · ใช้ hotspot ที่ติดไปกับกระเป๋า หรือวางตัวปล่อยใกล้กระเป๋า (กระเป๋าเดินไกลจากเครื่องที่ปล่อย Wi-Fi สัญญาณจะตก)
- โหลดหน้าให้เสร็จก่อน (ใกล้คอม) แล้วค่อยเดิน หน้าที่โหลดแล้วไม่ต้องใช้เซิร์ฟเวอร์ต่อ แต่ห้ามรีโหลด (ถ้าใช้ USB: ถอดสายได้หลังโหลด และ READY ครบแล้ว) ยังไม่มีโหมดออฟไลน์ (PWA)
- **ซ้อมจริงล่วงหน้า** กับคนครบชุดและเส้นทางจริง พร้อมจับเวลา 5 เมตรเพื่อวัดความเร็วกระเป๋า (คนเดินปกติ ~1.2 ม./วินาที)
